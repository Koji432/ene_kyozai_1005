# ene_kyozai_1005 — 火力発電を、内側から。

中学生向けの、操作できる3D火力発電教材。エネルギー変換と設備の動きを観察することに重点を置いています。クイズはありません。

**公開教材:** https://Koji432.github.io/ene_kyozai_1005/

## 観察できること

- ボイラーで燃料の化学エネルギーが熱に変わり、管内の水が加熱されて蒸気になる流れ。
- 蒸気が固定羽根と回転羽根を通り、タービンの軸を回す構造。
- タービンと発電機の磁極が同じ軸・同じ速度で回る関係。
- 固定されたコイルと回転する磁極、および回転と同期した交流電圧の模式波形。
- 復水器で蒸気が水へ戻り、給水ポンプを通ってボイラーへ戻る循環。
- 主系統の水と混ざらず、別の管内を流れる冷却水。
- 燃料のエネルギーが、電気と周囲へ出る熱などに分かれる関係。

## 使い方

1. 「内部を見る」で外装を開きます。「分解する」では外装を持ち上げます。
2. 3D画面のラベル、設備、または画面下の設備ボタンを選ぶと拡大できます。
3. ドラッグ／1本指で回転、ホイール／ピンチで拡大縮小。右ドラッグで視点を平行移動できます。
4. 一時停止、0.25倍・0.5倍・1倍でじっくり観察できます。
5. 「熱の投入量」を変えて、蒸気の流れと電気エネルギーの出力を比べられます。
6. キーボードでは3D画面にフォーカスし、矢印キーで回転、＋／−で拡大縮小します。

「教材について」に、モデルの簡略化と表現上の注意をまとめています。OSの「視差効果を減らす」などの設定が有効な場合は、一時停止した状態で始まります。

## モデルの範囲と正確さ

ボイラーを使う**汽力発電**の原理を表現しています。提供写真を参考に形状を作った学習用モデルで、実機のCAD・スキャン・寸法復元データではありません。実機の再熱・給水加熱、複数圧力段の詳細、排ガス処理などは省略しています。

- 大型同期発電機を電力系統につないだ定常運転を想定し、投入熱量を変えても回転数は一定です。軸の回転は見やすく遅くしてあり、実時間の回転数・流速は示していません。
- コイルは閉じた固定巻線として簡略化しています。赤・青の磁極は実機では電磁石です。波形は1組の固定コイルの電圧を示す模式図で、実機の三相巻線配置・負荷角・励磁制御は再現していません。
- 色と粒は観察用の目印です。蒸気は実際には無色透明です。黄色の粒は電気エネルギーの伝わる向きであり、電子が発電機から一方向に流れていく図ではありません。
- 冷却水と主系統の水は別経路で、熱だけが管壁を通ります。熱量の厳密な流体・熱力学計算は行いません。
- 熱収支は説明用の効率40%固定の例です。投入100に対し電気40、周囲へ出る熱など60。実際の効率・所内電力・負荷による変化は示していません。
- 熱投入量は異なる定常運転の比較です。起動・停止・過渡運転や安全操作を学ぶシミュレーターではありません。

## GitHub Pagesだけで公開

追加サーバー・データベース・APIキーは不要です。JavaScriptライブラリも同梱済みで、表示時の外部CDN依存はありません。

GitHubの **Settings → Pages → Deploy from a branch → main / (root) → Save** で公開できます。ファイルはすべて相対パスなので、リポジトリ名付きURLでも動きます。

手元では `index.html` を直接ブラウザーで開いても使えます。端末設定でローカルファイルの動作が制限される場合は、GitHub PagesのURLを使用してください。WebGL対応の現行Chrome・Edge・Safariを推奨します。

## ファイル

- `index.html` — 教材画面と説明
- `style.css` — PC・タブレット・スマートフォンの表示
- `app.js` — 3Dモデルとアニメーションの編集用ソース
- `app.bundle.js` — ライブラリを含む、配布・実行用のスクリプト
- `vendor/` — Three.js 0.180.0と関連ソース・MITライセンス
- `assets/` — 提供された参考写真・参考図、アイコン
- `.nojekyll` — GitHub Pagesで静的ファイルをそのまま配信する指定

ソースを編集した場合だけ、Node.jsで以下を実行して配布スクリプトを更新します。

```sh
npx --yes esbuild@0.25.11 app.js --bundle --minify --format=iife --outfile=app.bundle.js
```

公開・閲覧にはこのビルド作業もNode.jsも必要ありません。
